# S4-F5-C1 — Fix Input Bar Horizontal Scrolling

**PROMPT ID:** S4-F5-C1
**MODEL:** DeepSeek V4 Flash
**TYPE:** Pure-Logic
**DEPENDS ON:** none
**TOUCHES EXISTING CODE:** Yes — main_window.py (input_bar, TaskRowWidget.editor)

---

**OBJECTIVE:** Ensure the add-task input bar and edit-task input field support horizontal scrolling for long text.

**ROOT CAUSE:** Long task text may get clipped or cursor may jump to end due to stylesheet or size policy overrides.

**REQUIREMENTS:**

1. Audit `input_bar` (QLineEdit) setup in MainWindow:
   - Verify `QLineEdit` native horizontal scroll works
   - Check for any `setMaxLength`, `setReadOnly`, or stylesheet overrides that disable scroll
   - Ensure `setDragEnabled(True)` is set (allows text selection and scroll)

2. Audit `TaskRowWidget.editor` (QLineEdit) setup:
   - Same checks as above
   - Verify horizontal scroll works during inline edit

3. If horizontal scroll is not working, apply fixes:
   ```python
   self.input_bar.setHorizontalScrollBarPolicy(Qt.ScrollBarPolicy.ScrollBarAsNeeded)
   self.input_bar.setDragEnabled(True)
   ```

4. Check `theme.py` QLineEdit stylesheets:
   - Look for `max-width`, `overflow`, or `padding` that might clip text
   - Ensure no `setFixedWidth` on input bars

**FILES TO MODIFY:**
- `src/frontend/main_window.py` — input_bar setup, TaskRowWidget.editor setup (if needed)
- `src/frontend/theme.py` — verify QLineEdit styles (if needed)

**ACCEPTANCE CRITERIA:**
- Typing long text in add-task input bar: text scrolls horizontally
- Editing a long task: same horizontal scroll behavior
- Cursor stays at text position during scroll
- No visual glitches or layout jumps
- Works in all themes (Dark, Light, OLED)

**EDGE CASES:**
- Text exactly at widget width: no scroll needed
- Text much longer than widget width: smooth horizontal scroll
- Pasting long text: scrolls to show pasted content
