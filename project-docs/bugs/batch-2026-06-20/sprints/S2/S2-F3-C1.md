# S2-F3-C1 — Fix Dialog Shortcut Toggle

**PROMPT ID:** S2-F3-C1
**MODEL:** DeepSeek V4 Flash
**TYPE:** Pure-Logic
**WHY THIS MODEL:** Simple fix — add 3-line `closeEvent` override to GlassPanelDialog
**DEPENDS ON:** none
**CONFIDENCE IN ROOT CAUSE:** Certain
**CONTEXT:** `HistoryDialog` inherits `GlassPanelDialog` which doesn't emit `finished` on close.

---

**PROMPT TO PASTE:**
"""
OBJECTIVE: Fix shortcut toggle so Ctrl+H closes the History dialog (and any future GlassPanelDialog subclass).

ROOT CAUSE: `GlassPanelDialog` doesn't override `closeEvent`. Default `QDialog.closeEvent` calls `event.accept()` then `hide()`, but `hide()` does NOT emit `finished`. The toggle check in `open_history()` relies on `_history_dialog` being reset to `None` via `_on_side_dialog_closed()`, which is connected to the `finished` signal.

FIX: Add `closeEvent` override to `GlassPanelDialog` that calls `self.reject()`, which triggers `done()` → emits `finished` → `_on_side_dialog_closed()` fires → `_history_dialog = None`.

REQUIREMENTS:
- Add to `GlassPanelDialog` in `glass_panel_dialog.py`:
  ```python
  def closeEvent(self, event):
      event.accept()
      self.reject()
  ```
- This is 3 lines. No other changes needed.
- Verify that `SettingsDialog` still works (it already calls `self.reject()` in its own `closeEvent` — adding it to the parent class is harmless since the child's override takes precedence).

FILES TO MODIFY:
- `src/frontend/glass_panel_dialog.py` — add `closeEvent` method

TECH STACK & CONSTRAINTS:
- PyQt6, Python 3.11
- `QDialog.reject()` calls `done(0)` which emits `finished(int)`
- `SettingsDialog.closeEvent` already calls `self.reject()` — child override takes precedence, so no conflict
- `HistoryDialog` does NOT override `closeEvent` — so the parent's version will be used

EXPECTED OUTPUT:
- `closeEvent` added to `GlassPanelDialog`
- All GlassPanelDialog subclasses now emit `finished` on close
"""

**ACCEPTANCE CRITERIA:**
- `GlassPanelDialog.closeEvent` calls `self.reject()`
- Ctrl+H closes an open History dialog
- Ctrl+, still works for Settings (no regression)
- Settings dialog's unsaved-changes prompt still works
