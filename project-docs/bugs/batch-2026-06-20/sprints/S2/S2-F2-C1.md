**PROMPT TO PASTE:**
"""
OBJECTIVE: Design a position-preserving undo for task completion.

ROOT CAUSE: `restore_task_from_history()` at `main_window.py:3088-3099` does:
```python
self.tasks.append(restored_task)
```
No original index is saved. The task always goes to the end.

CURRENT ARCHIVE FLOW:
1. `toggle_task(task_ref, True)` → `archive_task(task_ref)`
2. `archive_task`: copies task dict, adds `completedAt`, saves to history, removes from `self.tasks`, deletes row widget
3. Stores `self._last_archived_task = archived_task` (for undo)
4. Shows `UndoToast` with `_undo_last_archive` callback
5. `_undo_last_archive` → `restore_task_from_history(task)`
6. `restore_task_from_history`: removes from history, appends to `self.tasks`, creates row widget

DESIGN REQUIREMENTS:
1. Save the original index at archive time (before removing from `self.tasks`)
2. Store it in `_last_archived_task` as a transient key (e.g., `_archivedFromIndex`)
3. On restore, insert at saved index instead of appending
4. Handle edge cases:
   - Index out of bounds (list shrunk while task was archived) — insert at end
   - Group mode: need to restore within the correct group
   - Multiple undos in sequence — each should restore to its own position

TECH STACK & CONSTRAINTS:
- `_last_archived_task` is an in-memory dict, not persisted to history.json
- Adding `_archivedFromIndex` is safe — it's transient
- In group mode, the index should be relative to the group's tasks, not the global list
- `tasks_for_group()` filters the master list — need to compute the global insert position

EXPECTED OUTPUT:
- Data flow design: where to save index, where to restore
- Insert logic for flat mode and group mode
- Edge case handling specification
"""
